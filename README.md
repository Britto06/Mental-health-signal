# Mental Health Signal

A student wellness analytics app that predicts a mental health score (0–10) based on daily habits like screen time, sleep, stress, and physical activity.

---

## Project Structure

```
Mental health signal/
├── api.py                  # FastAPI backend (prediction, reminders & history)
├── database.py             # MongoDB integration (students, predictions, reminders)
├── scheduler.py            # Automated reminder scheduler (periodic & daily checks)
├── services/               # Modular reminder notification services
│   ├── reminder_service.py # Reminder calculation, preferences & due processing
│   ├── email_service.py    # Non-diagnostic SMTP email reminders
│   └── whatsapp_service.py # Twilio WhatsApp reminders
├── test_system.py          # Automated test suite (10/10 tests)
├── train_model.py          # ML model training script
├── pipeline.pkl            # Trained Random Forest regression pipeline
├── requirements.txt        # Python dependencies
├── .env                    # Environment variables (MongoDB, SMTP, Twilio)
├── .env.example            # Environment variables template
├── .gitignore              # Git ignore file for secrets and environments
├── .venv/                  # Python virtual environment
└── mental-health-signal/   # React + Vite frontend
    ├── src/
    │   ├── MentalHealthSignal.jsx  # Main app component (prediction, reminders, history)
    │   ├── App.jsx
    │   ├── main.jsx
    │   └── index.css
    ├── package.json
    └── vite.config.js
```

## Notes

- The frontend runs in **demo mode** by default (local scoring, no backend needed).
- To connect to the live backend API, edit `API_BASE_URL` in `mental-health-signal/src/MentalHealthSignal.jsx` line 9:
  ```js
  const API_BASE_URL = "http://localhost:8000";
  ```
- The backend's `/predict` endpoint requires `pipeline.pkl` (generated by `train_model.py`). Without it, prediction returns a 503 error but the demo mode still works.

## Reminder & MongoDB Logging System

### Supported Reminder Frequencies
- **Daily**: Sends check-in reminder every 1 day (`reminder_interval_days = 1`)
- **Every 2 days**: Sends check-in reminder every 2 days (`reminder_interval_days = 2`)
- **Weekly**: Sends check-in reminder every 7 days (`reminder_interval_days = 7`)

### Supported Channels
- **Email**: Sent using SMTP (non-diagnostic educational reminder)
- **WhatsApp**: Sent using Twilio WhatsApp API (with graceful fallback if unconfigured)
- **Both**: Sends on both email and WhatsApp

### MongoDB Collections (`mental_health_signal`)
- **`students`**: Stores student contact details, reminder preferences, and next reminder timestamp.
- **`predictions`**: Stores chronological prediction logs including score, factors, and inputs.
- **`reminders`**: Logs all automated reminder attempts and delivery statuses (`sent`, `failed`).

### API Endpoints
- `POST /predict?student_id={id}`: Generates mental health score (0–10) and automatically logs prediction to MongoDB.
- `POST /reminders/preferences`: Save or update reminder preferences.
- `GET /reminders/preferences/{student_id}`: Retrieve current student reminder settings.
- `PUT /reminders/preferences/{student_id}`: Update student reminder settings.
- `POST /reminders/disable/{student_id}`: Disable reminders for a student.
- `POST /reminders/test/{student_id}`: Immediately trigger a test reminder.
- `GET /predictions/history/{student_id}`: Fetch chronological assessment history from MongoDB.
